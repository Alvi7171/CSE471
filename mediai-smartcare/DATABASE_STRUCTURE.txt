╔═══════════════════════════════════════════════════════════════════════════════╗
║                     TABLE 2: doctor_schedules                                  ║
╠═══════════════════════════════════════════════════════════════════════════════╣
║  Purpose: Define recurring weekly availability schedules                       ║
║  Records: 55 schedule slots (18 English + 37 Bengali doctors)                 ║
╚═══════════════════════════════════════════════════════════════════════════════╝

┌─────────────────────┬──────────────┬──────────────────┬──────────────────────┐
│ Column              │ Type         │ Constraints      │ Description          │
├─────────────────────┼──────────────┼──────────────────┼──────────────────────┤
│ schedule_id         │ INTEGER      │ PRIMARY KEY      │ Unique ID            │
│ doctor_id           │ INTEGER      │ FOREIGN KEY      │ Links to doctors     │
│ day_of_week         │ TEXT         │ CHECK IN (...)   │ Mon-Sun              │
│ start_time          │ TEXT         │ NOT NULL         │ HH:MM:SS             │
│ end_time            │ TEXT         │ NOT NULL         │ HH:MM:SS             │
│ slot_duration       │ INTEGER      │ DEFAULT 30       │ Minutes (15-60)      │
│ is_active           │ INTEGER      │ DEFAULT 1        │ 1=active, 0=deleted  │
│ created_at          │ TEXT         │ TIMESTAMP        │ Creation time        │
│ updated_at          │ TEXT         │ TIMESTAMP        │ Last update time     │
└─────────────────────┴──────────────┴──────────────────┴──────────────────────┘

Constraints:
  • FOREIGN KEY (doctor_id) REFERENCES doctors(doctor_id) ON DELETE CASCADE
  • UNIQUE (doctor_id, day_of_week, start_time)
  • CHECK (day_of_week IN ('Monday', 'Tuesday', 'Wednesday', 'Thursday', 
                           'Friday', 'Saturday', 'Sunday'))

Relationship Explanation:
  • One doctor can have MANY schedules (1:M)
  • One doctor can have MANY time slots (1:M)
  • Cascade delete: Deleting a doctor deletes all their schedules and slots


╔═══════════════════════════════════════════════════════════════════════════════╗
║                       CONFLICT PREVENTION LOGIC                                ║
╚═══════════════════════════════════════════════════════════════════════════════╝

When creating a new schedule, the system checks for time overlaps:

Existing Schedule:  [─────────────]  (Monday 09:00-13:00)
                        09:00    13:00

Attempt 1:         [────────]         ❌ CONFLICT (overlaps)
                     10:00  12:00

Attempt 2:                     [────────]  ✅ ALLOWED (no overlap)
                                 14:00  18:00

Attempt 3:    [──────]                  ✅ ALLOWED (no overlap)
               07:00 08:00

SQL Conflict Detection Query:
╔════════════════════════════════════════════════════════════════════════════╗
║ SELECT schedule_id FROM doctor_schedules                                   ║
║ WHERE doctor_id = ?                                                        ║
║ AND day_of_week = ?                                                        ║
║ AND is_active = 1                                                          ║
║ AND (                                                                      ║
║   -- Condition 1: New starts before existing ends                         ║
║   (start_time <= ? AND end_time > ?)                                      ║
║   OR                                                                       ║
║   -- Condition 2: New ends after existing starts                          ║
║   (start_time < ? AND end_time >= ?)                                      ║
║   OR                                                                       ║
║   -- Condition 3: New completely within existing                          ║
║   (start_time >= ? AND end_time <= ?)                                     ║
║ )                                                                          ║
╚════════════════════════════════════════════════════════════════════════════╝

If conflict found → Return HTTP 409 "Schedule conflict detected"
If no conflict → INSERT new schedule

╔═══════════════════════════════════════════════════════════════════════════════╗
║                              HOW TO ACCESS                                     ║
╚═══════════════════════════════════════════════════════════════════════════════╝

Method 1: Via Backend API
  • Start backend: cd backend && npm start
  • API endpoint: http://localhost:1355/api/schedule/doctors
  • Returns JSON data

Method 2: Direct SQL Query (Node.js)
  const db = require('./config/database');
  const doctors = db.prepare('SELECT * FROM doctors').all();
  console.log(doctors);

Method 3: SQLite CLI
  sqlite3 backend/mediai_smartcare.db
  sqlite> SELECT * FROM doctors;
  sqlite> .exit

Method 4: DB Browser for SQLite
  • Download: https://sqlitebrowser.org/
  • Open file: backend/mediai_smartcare.db
  • GUI for viewing/editing tables
